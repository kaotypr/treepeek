# Contributing to Treepeek

Thanks for helping. This file gets you from a fresh clone to a pull request.
[AGENTS.md](AGENTS.md) is the standard every change is held to, by people and coding agents
alike: the architecture, the IPC, security and git rules, code style and tests. Read it
before a change of any size.

Everyone taking part follows the [code of conduct](CODE_OF_CONDUCT.md). Security problems
are reported privately, as [SECURITY.md](SECURITY.md) explains, never in an issue or a pull
request.

## What you need

- A Mac with Apple Silicon, on macOS 13 (Ventura) or later.
- [Git](https://git-scm.com) 2.36 or later. The tests build real repositories with it.
- [Bun](https://bun.sh) 1.4.3 or later. Bun installs the packages and runs the scripts.
- [Node.js](https://nodejs.org) 24. Electron's build tools, Vitest and Playwright run on
  Node.

You do not need an Apple Developer account. Every local build, `bun run package` included,
is unsigned and runs on the Mac that built it.

## Set up

```sh
git clone https://github.com/kaotypr/treepeek.git
cd treepeek
bun install --frozen-lockfile
```

`bun install` also downloads Electron's binary (its `postinstall` step). Always install with
`--frozen-lockfile`, so you get exactly the versions in `bun.lock`.

## Run the app

```sh
bun run dev
```

starts Treepeek with hot reload. The development server relaxes the content security policy
to make hot reload work, so check anything that touches styles or scripts in a real build
as well (`bun run build`, then the end-to-end tests).

## Run the checks

| What                                 | Command                                                         |
| ------------------------------------ | --------------------------------------------------------------- |
| Lint and format check (Biome)        | `bun run lint`, and `bun run format` to fix formatting          |
| Type-check                           | `bun run typecheck`                                             |
| Unit and integration tests (Vitest)  | `bun run test`                                                  |
| End-to-end tests against a build     | `bun run build && bun run build:lab && bun run test:e2e`        |
| Package the unsigned app             | `bun run package` (writes `dist/mac-arm64/Treepeek.app`)        |
| End-to-end tests against the package | `APP_TARGET=packaged bun run test:e2e`, after `bun run package` |
| Licenses of everything the app ships | `bun run licenses:check`                                        |

**The tests use real git repositories.** Anything that reads git output is tested against
temporary repositories that the tests create with your `git` (`tests/support/git.ts` and
`tests/support/git-fixture.ts`), never against mocks. They are made in your temporary folder
and removed afterwards. Test git runs ignore your global and system git configuration and
use their own author name, so your own settings do not change the results. To run them with a different git, for example an older one to check the minimum
version, set `TREEPEEK_GIT=/path/to/git`.

**End-to-end tests run in the background.** They launch Treepeek with transparent,
click-through windows that never take focus, so you can keep working while they run. To
watch a run, use `TREEPEEK_E2E_SHOW=1 bun run test:e2e`.

Which checks a change needs:

- Every change: `bun run lint`, `bun run typecheck`, `bun run test`.
- Anything under `src/`: also `bun run build` and `bun run test:e2e`.
- Packaging, Electron fuses, the `app://` protocol, the preload, or a new runtime
  dependency: also `bun run package` and `APP_TARGET=packaged bun run test:e2e`.

Every bug fix comes with a test that fails without the fix.

## Dependencies and licenses

Treepeek is Apache-2.0, and so is what it ships alongside its own code. `bun run
licenses:check` fails when the app would ship a package, a syntax grammar or a color theme
under a license outside the allow-list in `build/license-allowlist.json`. A new license is
added there only as a reviewed exception, with the reason it is acceptable.

The app's third-party notices (`build/THIRD_PARTY_NOTICES`, shown in About ›
Acknowledgements) are generated by `bun run notices`, which `bun run package` runs first.

A new runtime dependency (`dependencies`, not `devDependencies`) changes what is packaged:
say why it is needed in the pull request.

## Commits

Commits follow [Conventional Commits](https://www.conventionalcommits.org):
`type(scope): subject`, with an imperative subject.

- Types: `feat`, `fix`, `test`, `docs`, `build`, `chore`, and the other Conventional
  Commits types where they fit.
- Scope: one of `main`, `core`, `preload`, `renderer`, `shared`, `ipc`, `build`, `test` or
  `docs`, or none for a change across several.
- One logical change per commit.

For example: `fix(core): keep the scan going when one repository cannot be read`.

There is no contributor license agreement and no sign-off. Under section 5 of the
[Apache License](LICENSE), anything you intentionally submit for inclusion in Treepeek is
licensed under the Apache License, Version 2.0, with no additional terms.

## Pull requests

- Open the pull request against `main`. The template asks what changed, which checks you
  ran and what they returned, and what you could not verify.
- CI runs on every pull request, forks included: Biome, the type-check, Vitest, the
  unsigned package, the end-to-end tests against it, the license check and Electronegativity.
  It uses no secrets, so a pull request from a fork gets the same results. When an
  end-to-end test fails, the run keeps its Playwright trace and the app's logs as an
  artifact.
- Keep a pull request to one purpose. A rule in AGENTS.md that turns out to be wrong is
  changed in the same pull request, with the reason.
